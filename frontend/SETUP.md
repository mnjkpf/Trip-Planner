# Frontend

Angular генеруємо не заздалегідь, а коли доходить черга (3-й місяць) —
щоб узяти актуальну версію, а не ту, що була на старті.

## Створення

```bash
npm install -g @angular/cli
cd frontend
ng new web --routing --style=scss --ssr=false --skip-git
cd web
```

`--skip-git` обов'язково: репозиторій уже є, другий усередині не потрібен.
`--ssr=false` — SSR тут нічого не дає й ускладнює деплой на S3.

## Залежності

```bash
# Карта. Leaflet, не Google Maps — той вимагає картку і білінг.
npm i leaflet
npm i -D @types/leaflet

# UI. Бери щось одне.
ng add @angular/material

# Дати в маршруті
npm i date-fns
```

Тайли карти: `https://tile.openstreetmap.org/{z}/{x}/{y}.png` годяться для
розробки, але в OSM Tile Usage Policy заборонене важке використання.
Для демо візьми безкоштовний тариф MapTiler або Geoapify — ключ той самий,
що вже є в `.env`.

**Атрибуція обов'язкова** — це умова ліцензії ODbL, а не побажання:

```ts
L.tileLayer(url, {
  attribution: '&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors'
}).addTo(map);
```

## Проксі на час розробки

Скопіюй `proxy.conf.json` (лежить поруч) у `frontend/web/` і додай у
`angular.json` → `projects.web.architect.serve.options`:

```json
"proxyConfig": "proxy.conf.json"
```

Тоді фронт ходить на `/api/...` без CORS, а gateway лишається на 8080.

## Екрани, яких достатньо

Не більше шести — на фронт легко втратити місяць, а рев'юер оцінює бекенд:

1. Логін / реєстрація
2. Пошук місць + карта з маркерами
3. Картка місця (опис, фото, години роботи)
4. Список подорожей
5. Редактор подорожі: вішліст, дні, drag-and-drop пунктів
6. Згенерований маршрут: таймлайн по днях + погода + кнопка «перепланувати»

## Що показати обов'язково

- `202 Accepted` і спінер на генерації маршруту, потім оновлення по SSE —
  саме це доводить, що асинхронність справжня, а не намальована;
- бейдж «дані з кешу / оновлено щойно» — видно роботу кеш-шару;
- повідомлення «погода на середу змінилась, є краща розкладка» — фіча,
  заради якої в проекті є Kafka.
